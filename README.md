# Verilog Interpreter

Run Verilog in your browser: **https://goodman-pro.github.io/verilog-interpreter/**

Write a design and a testbench, press Run, and get the `$display` output and waveforms. The simulator is a
single dependency-free JavaScript file; nothing is installed and nothing is uploaded.

The editor colours the code (keywords, types, numbers, strings, module names, and function, task and system-task
names), draws a guide line at every level of indentation, closes brackets and quotes, keeps indentation, and
suggests keywords, system tasks and the names in your code as you type (Tab inserts, Ctrl+Space opens the list).

## What it is

`verilog.js` is an event-driven, 4-state (0, 1, x, z) Verilog-2001 simulator:

- **Preprocessor and lexer**: `` `define `` (with arguments), `` `ifdef/`ifndef/`elsif/`else/`endif ``, `` `timescale ``,
  `` `default_nettype ``, `` `unconnected_drive ``.
- **Parser**: modules, ANSI and classic port lists, parameters, `generate` for/if/case, functions, tasks, gate primitives.
- **Elaborator**: parameter overrides, hierarchy, hierarchical names, implicit nets, constant functions.
- **Simulator**: active / inactive (`#0`) / nonblocking / postponed regions, inertial net delays with separate
  rise, fall and turn-off values, wire resolution with multiple drivers and tri-state, `wand`/`wor`,
  `tri0`/`tri1`/`pullup`/`pulldown`, `supply0`/`supply1`, two-way `inout` ports (including part-selects and
  concatenations; an output connected to a whole net of its own width is one net with it, as in Icarus),
  IEEE 1364-2005 expression width and signedness rules, reals, memories, `automatic` tasks and functions,
  `fork`/`join`, and `disable` (including of a block, task or named fork that is running in another process).

Supported system tasks and functions: `$display $write $strobe $monitor` (and the `b/h/o` forms), `$monitoron/off`,
`$time $stime $realtime $timeformat $printtimescale`, `$finish $stop`, `$random $urandom $urandom_range $dist_uniform`,
`$signed $unsigned`, `$clog2 $bits`, `$rtoi $itor $realtobits $bitstoreal`, `$sformat $swrite`, and the real math
functions (`$sqrt $pow $ln ...`).

Not supported, and reported as an error: `$readmemh/$readmemb` and file I/O, `` `include ``, user-defined
primitives, drive strengths, `trireg`, switch primitives (`tran`, `cmos`), `defparam`, `force/release`,
procedural `assign/deassign`, arrays of instances, port expressions in a module header, the other `$dist_*`
functions, the raw `%u`/`%z` formats, and SystemVerilog (common habits such as `logic`, `always_comb` and `i++`
get a message that says so). `specify` blocks are skipped: path delays and timing checks are not modelled.

Where the standard leaves behaviour open (time-zero ordering, default print widths, `$random` values) the
interpreter follows [Icarus Verilog](https://steveicarus.github.io/iverilog/), so results match what most people
see locally or on EDA Playground. Known differences from Icarus:

- Arithmetic on unsized constants uses the IEEE 32-bit rule (`2147483647 + 1` is 32 bits wide); Icarus widens it.
- Recursion is limited by the JavaScript stack to roughly a thousand levels.
- Simulation time is a JavaScript number, so it is exact only up to 2^53 time-precision ticks.
- Events that happen at the same instant in different processes may be ordered differently (the standard
  allows any order). At time 0, a wire computed from not-yet-initialised signals reads `x` rather than `z`.
- Strengths are not modelled, so a `bufif` with an unknown enable gives `x` where Icarus can resolve a pull.
- `%s` prints an embedded NUL byte as a space for constants as well as for variables, and a string stored in a
  wider parameter prints as a number (Icarus prints nothing).
- A delay in a net declaration (`wire #3 w;`) is applied; Icarus rejects it.
- A loop that runs more than 20 million steps without simulation time advancing is stopped with an error, so that
  an endless loop cannot hang the page (from Node, raise `maxStepOps`).
- `$ceil` of a literal between -1 and 0 gives `-0.0`, as it does for a variable; Icarus prints `0.0` for the literal.

## Files

| File | Purpose |
| --- | --- |
| `verilog.js` | The whole interpreter. `Verilog.run(source, options)` returns `{output, error, errorLine, time, finished, waves}`. |
| `worker.js` | Runs the simulation in a Web Worker so the page stays responsive and Stop works. |
| `index.html` | The page: editor, examples, output console, waveform viewer. |
| `highlight.js` | The editor's syntax colouring and suggestion word lists. `node highlight.js` runs its self-check. |
| `test.js` | `node test.js` runs the corpus; `node test.js file.v` runs one file. |
| `tests/` | 276 programs with expected output generated by Icarus Verilog (`tests/gen-expected.sh`). |

## Use it from Node

```js
const Verilog = require('./verilog.js');
const r = Verilog.run('module t; initial $display("%0d", 6 * 7); endmodule');
console.log(r.output);   // 42
```

Options: `maxOps` (total step budget, default 5e7), `maxStepOps` (steps allowed without time advancing, default 2e7),
`maxTime`, `maxOutput`, `waves: false` to skip waveform recording, `onOutput(text)` to stream output.

## Tests

```
node test.js
```

Every `.expected` file is the real output of Icarus Verilog 12 for the matching `.v` file. To regenerate them
(needs `iverilog` and `vvp`): `bash tests/gen-expected.sh`.

## How it was built

A collaboration between AI models, directed by the repository owner:

- **Claude** (Anthropic) wrote the interpreter, the page and this README.
- **GPT-6 Astra** (OpenAI, via Codex) wrote the first 82 conformance cases in `tests/`, independently of the
  interpreter's code, using Icarus Verilog as the oracle.
- **GPT 6.2 Astra** (OpenAI, via Codex) reviewed the interpreter adversarially in three rounds and reported 69, 57
  and 48 defects, each with a minimal program. It then checked the last batch of fixes before they were published
  and found 34 more problems, 13 of them regressions that those fixes had introduced.
- Teams of Claude reviewers ran about 5,300 further programs against Icarus over the same rounds and reported
  56, 47, 39 and 18.
- The confirmed defects were fixed after each round, and every repro that Icarus accepts without a warning and
  that now matches became a regression test: cases 085-160 from round one, 161-204 from round two and 205-276
  from round three (the `gpt_`/`gpt2_`/`gpt3_` and `hunt_`/`hunt2_`/`hunt3_` prefixes say who found each one;
  `probe3_` cases were written while fixing).
